# خطة معمارية تطبيق الحسابات (Accounts App)

تم إعداد هذه الخطة لتكون المرجع الأساسي والشامل لبناء تطبيق `apps/accounts` كمركز رئيسي للأمان، تسجيل الدخول، إدارة الملف الشخصي، وإعدادات المستخدمين في منصة **Rukny.io**.

---

## 1. مسار المستخدم (User Flow)

تم تصميم المسار ليكون سلساً، آمناً، وذكياً في توجيه المستخدم:

1. **الخطوة الأولى (إدخال البريد الإلكتروني):**
   - يدخل المستخدم بريده الإلكتروني.
   - يقوم النظام بالتحقق المبدئي لمعرفة حالة الحساب وطرق التحقق المتاحة.
2. **الخطوة الثانية (صفحة Check Email):**
   - يتم إرسال رمز/رابط إلى البريد الإلكتروني.
   - تظهر شاشة التحقق، وتحتوي على زر بارز: **"تجربة طريقة أخرى للتحقق"**.
3. **الخطوة الثالثة (التحقق البديل):**
   - عند الضغط على الزر، تنبثق قائمة بالخيارات المتاحة للمستخدم (إن وجدت):
     - المصادقة الثنائية (2FA Authenticator App).
     - رموز الاحتياط (Backup Codes).
     - رمز التحقق عبر الواتس اب (WhatsApp OTP).
4. **الخطوة الرابعة (ما بعد التحقق):**
   - **إذا كان المستخدم جديداً (New User):** يتم توجيهه إلى مسار **"إكمال الملف الشخصي"** (Onboarding)، والذي يشمل:
     - إكمال البيانات الشخصية الأساسية.
     - تهيئة المتجر أو مساحة العمل.
   - **إذا كان المستخدم مسجلاً مسبقاً (Existing User):** يتم تسجيل دخوله فوراً وتوجيهه إلى لوحة التحكم المناسبة.
5. **الخطوة الخامسة (التزامن والتوجيه الديناميكي):**
   - يتم توجيه المستخدم بناءً على نوع حسابه واهتمامه إلى أحد الأقسام: `apps/app`, `apps/business`, `apps/developers`, أو `apps/forms`.

---

## 2. خطة التصميم (Design Plan)

لأن هذا التطبيق هو واجهة الأمان الأولى للمنصة، يجب أن يكون التصميم عصرياً (Premium Aesthetics) ويبعث على الثقة.

- **الهوية البصرية:** استخدام ألوان المنصة المعتمدة (Olive, Gray Violet, Soft Lime) مع دعم كامل للوضع الداكن والفاتح (Dark/Light Modes).
- **الأنيميشن (Micro-animations):** استخدام انتقالات سلسة (Framer Motion) بين خطوات إدخال البريد والتحقق لإعطاء إحساس بالسرعة.
- **التخطيط (Layout):**
  - **شاشات المصادقة:** تصميم ممركز (Centered Card) مع خلفيات زجاجية (Glassmorphism) وعناصر بصرية جذابة.
  - **إكمال الملف الشخصي:** تصميم بنظام "الخطوات" (Stepper/Wizard) مع شريط تقدم يوضح للمستخدم مكانه.
  - **إعدادات الأمان:** تصميم يحتوي على قائمة جانبية (Sidebar) تتيح التبديل بين: الأمان (2FA، الأجهزة المتصلة)، الملف الشخصي، وإعدادات التنبيهات.

## 3. خطة المكونات (Components Architecture)

سيتم بناء المكونات باستخدام React/Next.js مع مكتبة `@heroui/react` لتوفير واجهات متناسقة:

### مكونات المصادقة (Auth Components)
- `AuthLayout`: الغلاف الرئيسي لجميع صفحات تسجيل الدخول، يتعامل مع الخلفية وضبط التمركز.
- `EmailEntryForm`: مكون مخصص لاستقبال البريد الإلكتروني والتحقق من صحته محلياً.
- `OtpVerificationForm`: مكون للتحقق من الرمز المدخل مع مؤقت تنازلي (Countdown) لإعادة الإرسال.
- `AlternativeAuthModal`: نافذة منبثقة (Modal/Drawer) تعرض خيارات التحقق الأخرى (2FA, WhatsApp, Backup) بناءً على إعدادات حساب المستخدم.

### مكونات إكمال الملف (Onboarding Components)
- `OnboardingWizard`: المكون الذي يدير حالة الخطوات.
- `ProfileSetupForm`: لإدخال الاسم، الصورة، والمعلومات الشخصية.
- `StoreSetupForm`: لإعداد تفاصيل المتجر/العمل التجاري.

### مكونات إعدادات الحساب (Settings Components)
- `SecuritySettings`: مكون لإدارة تفعيل وإلغاء تفعيل الـ 2FA، ورؤية الأجهزة النشطة.
- `ProfileSettings`: تعديل البيانات، وتحديث البريد الإلكتروني.

## 4. خطة الـ API والأمان (API & Security Plan)

سيتم بناء هذه العمليات بالاعتماد على معمارية `NestJS` الحالية والـ `BFF Proxy`:

### 4.1. مسارات المصادقة والتسجيل (Auth Endpoints)
1. **`POST /api/v1/auth/initiate`**
   - **المدخلات:** `email`
   - **الوظيفة:** يتحقق من وجود البريد، يرسل رمز OTP للبريد، ويحدد حالة المستخدم (جديد/موجود).
   - **المخرجات:** `{ sessionId, isNewUser, availableMethods: ['email', '2fa', 'whatsapp'] }`
   
2. **`POST /api/v1/auth/whatsapp/send`**
   - **المدخلات:** `sessionId`
   - **الوظيفة:** يرسل رمز OTP عبر WhatsApp للرقم المربوط بالحساب إن وجد.

3. **`POST /api/v1/auth/verify`**
   - **المدخلات:** `sessionId`, `code`, `method` (email, 2fa, whatsapp, backup)
   - **الوظيفة:** التحقق من الرمز وتوليد الكوكيز (Access & Refresh Tokens).
   - **المخرجات:** `{ needsProfileCompletion: boolean, nextRedirect: '/app' | '/business' }`

### 4.2. مسارات إكمال الملف الشخصي (Profile Endpoints)
1. **`POST /api/v1/users/profile/complete`**
   - **الوظيفة:** تحديث بيانات المستخدم الجديد (الاسم، التفاصيل) وإنشاء سجل المتجر/المساحة المرتبطة به.

### 4.3. المزامنة والتوجيه (Synchronization & Routing)
- **مشاركة الجلسة (Cross-App Session):** يتم تعيين الكوكيز الأمنية (`httpOnly`) على النطاق الجذري `Domain=.rukny.io`، مما يعني أن بمجرد تسجيل الدخول في `accounts.rukny.io`، ستكون الجلسة فعالة وتلقائية في `app.`, `business.`, `developers.`, `forms.`.
- **التحويل الذكي (Smart Redirect):** بناءً على رد الـ API بعد `verify`، سيتم حفظ الرابط المطلوب مسبقاً (Callback URL) أو تحويل المستخدم حسب نوعه:
  - أصحاب المتاجر -> `apps/business`
  - المستخدم العادي / مدير الروابط -> `apps/app`
  - المطورين -> `apps/developers`
  - إدارة النماذج -> `apps/forms`
- **حماية المسارات (Route Protection):** الاستفادة من `proxy.ts` (BFF) الحالي لمنع الدخول لصفحات الـ Dashboard دون استكمال الملف الشخصي، عبر وسيط (Middleware) يتحقق من حالة `profileCompleted`.

## 5. الخطوات التنفيذية المقترحة للبدء
1. **إنشاء الواجهات الأساسية (UI/UX):** بناء صفحات إدخال البريد وصفحات `Check Email`.
2. **ربط الـ API الخاص بـ Initiate & Verify:** تعديل NestJS لدعم مسار التحقق المكون من خطوتين والتحقق من حالة المستخدم (جديد/قديم).
3. **تطوير واجهات الخيارات البديلة (Alternative Auth):** تصميم وبناء الشاشة المنبثقة للـ 2FA و WhatsApp.
4. **بناء خطوة إكمال الملف (Onboarding):** برمجة الـ Wizard والتأكد من إرسال البيانات للملقم.
5. **تطبيق منطق التحويل المركزي (Routing Logic):** ضبط Middleware لإدارة التوجيه السلس إلى الأقسام المختلفة بعد المصادقة.
